## 2026-03-13 — Task 1.2: Restructure Reticulum init for supervised startup

**Changes:**
- `lib/rns/identity_store.ex`: Added `configure/1` API that accepts a storage path and loads
  known destinations from disk using Msgpax (matching Python's `Identity.load_known_destinations()`).
  Added `save_known_destinations/0` and `storagepath/0` APIs. Known destinations are serialized
  as msgpack maps keyed by destination hash, with values `[timestamp, packet_hash, public_key, app_data]`.
  Destinations with wrong hash length (not 16 bytes) are filtered out during loading.
- `lib/rns/transport.ex`: Added `configure/1` API that accepts keyword opts (`:storage_path`,
  `:cachepath`, `:transport_enabled`) and loads persisted data (packet hashlist, path table,
  tunnel table) from disk. Added `load_persisted_data/1` private function using existing
  CacheManagement and PathManagement persistence functions.
- `lib/rns/reticulum.ex`: Added `configure_subsystems/1` called from `init/1` after config is
  loaded (but before interface startup). It calls `IdentityStore.configure/1` with the storage
  path and `Transport.configure/1` with storage path, cache path, and transport_enabled flag.
  Updated `persist_data/1` to also save known destinations via `IdentityStore.save_known_destinations/0`
  and fixed file names to match CacheManagement conventions (`destination_table`, `tunnels`).
- `test/rns/identity_store_test.exs`: New test file with 8 tests covering configure, load, save,
  round-trip persistence, hash length filtering, and error handling.
- `test/rns/application_test.exs`: Added 4 tests verifying subsystem configuration on boot
  (IdentityStore has storagepath, storagepath matches Reticulum's, Transport ETS accessible, no crashes).

**Result:** `mix test` passes with 0 failures (2981 tests, 13 pre-existing skipped fixture tests).

## 2026-03-13 — Task 1.3: Fix shared-instance detection and local IPC

**Changes:**
- `lib/rns/reticulum.ex`:
  - Fixed port key mismatch: `start_shared_server/1` passed `:listen_port` but
    `LocalServerInterface` expected `:bindport`. Changed to `:bindport`.
  - Fixed abstract Unix socket path: when `use_af_unix` is true, the default socket
    path `"default"` is now converted to `<<0>> <> "rns/default"` (abstract Unix socket
    matching Python's `\0rns/default`). Instance names from config are also prefixed.
  - Added `out: true` to interface options in both `start_shared_server/1` and
    `start_shared_client/1`, matching Python's `interface.OUT = True`.
  - Added `require_shared_instance` support: when set, if this instance becomes the
    server (no existing daemon), it detaches and returns `{:stop, ...}` instead of
    running. Matches Python's `require_shared_instance` parameter.
  - Added `detach_interface/1` helper for single-interface detach.
- `lib/rns/interfaces/local_interface.ex`:
  - `LocalServerInterface.init/1` and `LocalClientInterface.init/1` now accept `:out`
    option (defaults to false, matching previous behavior).
  - `LocalServerInterface.init/1` now returns `{:stop, reason}` when listen fails
    (previously returned `{:ok, state}` with an offline server, breaking detection).
  - `do_listen_tcp/2` and `do_listen_unix/2` return `{:ok, state}` or `{:error, reason}`
    instead of always returning state.
  - Removed `reuseaddr: true` from server TCP listen options — on macOS, `SO_REUSEADDR`
    allows two sockets to bind the same port, defeating shared-instance detection.
  - Added `handle_info({:set_field, field, value})` to both server and client interfaces
    for runtime field updates (previously silently dropped by catch-all handler).
  - Fixed abstract socket path handling in `do_listen_unix/2`: only removes existing
    socket files for non-abstract paths.
- `test/rns/interfaces/local_interface_test.exs`: Added 5 tests for OUT flag via opts
  and `:set_field` handler on both server and client interfaces.
- `test/rns/reticulum_test.exs`: Added 8 tests covering shared-instance detection
  (becomes server, connects as client, standalone fallback, require_shared_instance,
  port consistency between server/client) and mode flag query APIs.

**Result:** `mix test` passes with 0 failures (2994 tests, 13 pre-existing skipped fixture tests).

## 2026-03-13 — Task 1.4: Wire the packet send path end to end

**Changes:**
- `lib/rns/packet.ex`:
  - Replaced `transport_outbound/1` stub (which always returned `false`) with a real call
    to `RNS.Transport.outbound/2`. The stub was the only thing preventing `Packet.send/1`
    from working end to end.
  - Added `transport_opts/0` private function that queries `RNS.Reticulum` for

  - Fixed receipt return: since Elixir structs are immutable (unlike Python's mutable
    objects), `do_send/1` now looks up the receipt from Transport's ETS table after
    successful send, rather than reading the never-set `packet.receipt` field.
  - Fixed `resend/1` with the same Transport.outbound wiring and receipt lookup.
  - Removed all "Phase 4" placeholder comments.
- `test/rns/packet_test.exs`:
  - Changed from `async: true` to `async: false` (send tests need Transport ETS tables).
  - Added setup block to clear Transport ETS tables between tests.
  - Added 8 tests covering: send via registered interface, send with receipt creation,
    send with no interfaces (returns false), send already-sent packet (raises), send
    over closed link (drops), auto-packing unpacked packets, resend raises if not sent,
    resend of previously sent packet.

## 2026-03-13 — Task 1.5: Wire Destination.announce through the send path

**Changes:**
- `lib/rns/packet.ex`:
  - Fixed `Packet.pack/1` to set `destination_type` on the packet struct. Previously,
    `pack` encoded the destination type into the flags byte but never set the struct field,
    leaving it nil. This caused `Transport.outbound_broadcast`'s `should_transmit_on_interface?`
    to see nil for `destination_type`. For announces this was harmless (short-circuit on
    `packet_type == @announce`), but incorrect for data packets in link/boundary checks.
- `test/rns/destination_test.exs`:
  - Added 6 end-to-end tests for `Destination.announce/2` with `send: true`:
    - Announce transmits through a registered interface
    - Announce returns false when no interfaces are registered
    - Announce broadcasts to all registered interfaces (not path-routed)
    - Announce raw bytes can be unpacked as a valid announce packet with correct fields
    - Announce with app_data transmits correctly with expected payload size
    - Announce with path_response context transmits with correct context byte

**Tracing:** Verified the full chain `Destination.announce/2` → `build_announce_packet` →
`maybe_send_announce` → `Packet.send/1` → `Transport.outbound/2` → `outbound_broadcast/1` →
`transmit/2` → interface `process_outgoing` is complete with no stubs or breaks. Announce
packets correctly bypass the path table via `should_use_path_table?` returning false for
`packet_type == @announce`.

**Result:** `mix test` passes with 0 failures (3030 tests, 13 pre-existing skipped fixture tests).

## 2026-03-14 — Task 1.6: Register interfaces with Transport during startup

**Changes:**
- `lib/rns/reticulum.ex`:
  - Added `register_interface_with_transport/2` function that gets the interface's GenServer
    state via `:get_state`, converts from struct to plain map, merges in optional post-init
    updates (out, mode, IFAC settings, etc.), adds a `:pid` field, computes hash if missing,
    and calls `RNS.Transport.register_interface/1`.
  - In `start_shared_server/1`: calls `register_interface_with_transport/1` after successful
    server interface startup.
  - In `start_shared_client/1`: calls `register_interface_with_transport/1` after successful
    client interface startup.
  - In `synthesize_interface/3`: after `apply_interface_post_init` and `start_interface_by_type`,
    calls `register_interface_with_transport/2` with post-init updates merged in so Transport
    has correct `out`, `mode`, IFAC, announce rate, and ingress control settings.
  - In `detach_all_interfaces/1`: now calls `RNS.Transport.deregister_interface/1` for each
    registered interface before detaching, ensuring clean ETS cleanup during shutdown.
  - Changed `apply_interface_post_init/3` to send individual `{:set_field, key, value}`
    messages instead of a single `{:apply_config, updates}` message (which had no handler
    and was silently dropped). Interfaces with `set_field` handlers now actually apply config.
- `lib/rns/interfaces/local_interface.ex`:
  - Added `handle_info({:process_outgoing, raw}, state)` to `LocalClientInterface`, calling
    the behaviour's `process_outgoing/2` and updating txb stats. This enables Transport's
    `call_process_outgoing` to transmit through registered client interfaces via pid.
- `lib/rns/interfaces/pipe_interface.ex`:
  - Added `handle_info({:set_field, field, value}, state)` for runtime config updates.
  - Added `handle_info({:process_outgoing, raw}, state)` for Transport transmit.
- `test/rns/reticulum_test.exs`: Added 5 tests covering:
  - Shared server interface is registered with Transport after start
  - Shared client interface is registered with Transport after start
  - Interfaces are deregistered during Reticulum shutdown
  - Configured interface (PipeInterface) is registered after synthesis
  - process_outgoing message is handled by LocalClientInterface

**Result:** `mix test` passes with 0 failures (3035 tests, 13 pre-existing skipped fixture tests).
