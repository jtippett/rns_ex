## 2026-03-13 — Task 1.2: Restructure Reticulum init for supervised startup

**Changes:**
- `lib/rns/identity_store.ex`: Added `configure/1` API that accepts a storage path and loads
  known destinations from disk using Msgpax (matching Python's `Identity.load_known_destinations()`).
  Added `save_known_destinations/0` and `storagepath/0` APIs. Known destinations are serialized

  tunnel table) from disk. Added `load_persisted_data/1` private function using existing
  CacheManagement and PathManagement persistence functions.
- `lib/rns/reticulum.ex`: Added `configure_subsystems/1` called from `init/1` after config is
  loaded (but before interface startup). It calls `IdentityStore.configure/1` with the storage
  path and `Transport.configure/1` with storage path, cache path, and transport_enabled flag.
  Updated `persist_data/1` to also save known destinations via `IdentityStore.save_known_destinations/0`
  and fixed file names to match CacheManagement conventions (`destination_table`, `tunnels`).
- `test/rns/identity_store_test.exs`: New test file with 8 tests covering configure, load, save,
  round-trip persistence, hash length filtering, and error handling.
- `test/rns/application_test.exs`: Added 4 tests verifying subsystem configuration on boot
  (IdentityStore has storagepath, storagepath matches Reticulum's, Transport ETS accessible, no crashes).

## 2026-03-13 — Task 1.3: Fix shared-instance detection and local IPC

**Changes:**
- `lib/rns/reticulum.ex`:
  - Fixed port key mismatch: `start_shared_server/1` passed `:listen_port` but
    `LocalServerInterface` expected `:bindport`. Changed to `:bindport`.
  - Fixed abstract Unix socket path: when `use_af_unix` is true, the default socket
    path `"default"` is now converted to `<<0>> <> "rns/default"` (abstract Unix socket
    matching Python's `\0rns/default`). Instance names from config are also prefixed.
  - Added `out: true` to interface options in both `start_shared_server/1` and
    `start_shared_client/1`, matching Python's `interface.OUT = True`.
  - Added `require_shared_instance` support: when set, if this instance becomes the
    server (no existing daemon), it detaches and returns `{:stop, ...}` instead of
    running. Matches Python's `require_shared_instance` parameter.
  - Added `detach_interface/1` helper for single-interface detach.
- `lib/rns/interfaces/local_interface.ex`:
  - `LocalServerInterface.init/1` and `LocalClientInterface.init/1` now accept `:out`
    option (defaults to false, matching previous behavior).
  - `LocalServerInterface.init/1` now returns `{:stop, reason}` when listen fails
    (previously returned `{:ok, state}` with an offline server, breaking detection).
  - `do_listen_tcp/2` and `do_listen_unix/2` return `{:ok, state}` or `{:error, reason}`
    instead of always returning state.
  - Removed `reuseaddr: true` from server TCP listen options — on macOS, `SO_REUSEADDR`
    allows two sockets to bind the same port, defeating shared-instance detection.
  - Added `handle_info({:set_field, field, value})` to both server and client interfaces
    for runtime field updates (previously silently dropped by catch-all handler).
  - Fixed abstract socket path handling in `do_listen_unix/2`: only removes existing
    socket files for non-abstract paths.
- `test/rns/interfaces/local_interface_test.exs`: Added 5 tests for OUT flag via opts
  and `:set_field` handler on both server and client interfaces.
- `test/rns/reticulum_test.exs`: Added 8 tests covering shared-instance detection
  (becomes server, connects as client, standalone fallback, require_shared_instance,
  port consistency between server/client) and mode flag query APIs.

**Result:** `mix test` passes with 0 failures (2994 tests, 13 pre-existing skipped fixture tests).

## 2026-03-13 — Task 1.5: Wire Destination.announce through the send path

**Changes:**
- `lib/rns/packet.ex`:

    - Announce raw bytes can be unpacked as a valid announce packet with correct fields
    - Announce with app_data transmits correctly with expected payload size
    - Announce with path_response context transmits with correct context byte

**Tracing:** Verified the full chain `Destination.announce/2` → `build_announce_packet` →
`maybe_send_announce` → `Packet.send/1` → `Transport.outbound/2` → `outbound_broadcast/1` →
`transmit/2` → interface `process_outgoing` is complete with no stubs or breaks. Announce
packets correctly bypass the path table via `should_use_path_table?` returning false for
`packet_type == @announce`.

## 2026-03-14 — Task 2.2: Load and save packet hashlist, path table, and tunnel table

**Changes:**
- `lib/rns/reticulum.ex`:

    `RNS.Transport.start_jobs()` to start Transport's periodic maintenance jobs
    (link checks, receipt checks, announce checks, table culling, cache cleaning).
    Previously, `Transport.start_jobs()` was never called from anywhere, leaving
    Transport's periodic maintenance completely unwired.
  - Set `jobs_started: true` in Reticulum state after scheduling periodic jobs,
    so the flag accurately reflects runtime state.
- `test/rns/transport_persistence_test.exs`: New test file with 15 tests covering:
  - Packet hashlist save/load round-trip (data survives clear and reload)
  - Missing hashlist file returns `{:error, :enoent}`, no crash
  - Corrupt hashlist file (invalid msgpack) returns error, no crash
  - Path table save/load round-trip with registered interface
  - Expired path entries are not restored on load
  - Path entries with missing (deregistered) interface are not restored on load
  - Missing path table file returns error, no crash
  - Tunnel table save/load round-trip (tunnel_id, paths, hops preserved)
  - Missing tunnel file returns error, no crash
  - Packet hashlist loaded via `Transport.configure/1` (full integration path)
  - Configure with no persistence files doesn't crash (first boot scenario)
  - Reticulum periodic job timer is running after boot (`jobs_started == true`)
  - Reticulum persist interval constants match Python (12h persist, 5m gracious)
  - Transport periodic jobs are started after boot (`jobs_started == true`)
  - Transport terminate saves state files to disk

**Verification:** The persistence infrastructure (save/load functions in CacheManagement
and PathManagement, loading in Transport.configure, saving in Transport.terminate and
Reticulum.terminate, periodic persistence in Reticulum.handle_info(:run_jobs)) was already
fully implemented from the porting phase. The key gap was that Transport.start_jobs() was
never called, leaving Transport's periodic maintenance (link timeout checks, receipt checks,
announce processing, table culling) completely unwired. Reticulum's own periodic persistence
timer (12h interval via :run_jobs) was already working.
